# 电商文案语义编译

把事实翻译成消费者一眼能懂的话，不改变产品事实，不代替策划分配页面任务。

## 使用前读取

实现或审查编译器时，先读 [文案语义合同](references/copy-semantic-contract.md)。

## 输入合同

每次只处理一个已锁定的屏幕任务：

- `screenId / subjectKey / userQuestion`：服务端任务身份，不得改写。
- `claimScope / evidenceIds / evidenceFacts`：本屏唯一事实授权范围。
- `pageTask`：本屏在15屏决策链中的作用。
- 相邻屏摘要：只用于避重，不得借用其事实。

用户上传图片里清晰可识别的参数、材质、功能和卖点属于甲方基础资料，可原意进入文案。不得因为没有外部检测报告而自动删除普通民用属性；不得借口“优化语义”新增图片外参数、认证、功效、评价或交易承诺。

## 编译流程

1. 先回答 `userQuestion`，确定这一屏用户真正想知道什么。
2. 只读取本屏 `evidenceIds` 对应事实；creative 屏不得引入产品功效。
3. 按三层语义生成 `CopyBlock`：
   - `headline`：用户结论，4–10字，回答“这对我有什么用”。
   - `subheadline`：事实解释，最多20字，回答“为什么成立”。
   - `body`：生活说明，最多45字，用完整句连接场景/动作、事实和用户结果。
   - `keyPoints`：1–3条直接事实或选择提示，不另造卖点。
4. 做屏内去重：标题、副标题、正文不得同义复述。
5. 做全系列去重：不能只换近义词重复相邻屏任务。
6. 做残句检查：所有字段不得以连接词、未闭合符号或硬截断片段结尾。

## 输出合同

只输出：

```ts
type CopyBlock = {
  headline: string;
  subheadline: string;
  body: string;
  keyPoints: string[];
};
```

不得输出场景、镜头、生图提示词、证据解释或内部流程语言。文案一旦通过策划校验即为唯一真相源；执行阶段只能原样引用，不能再次改写。

## 阻断条件

以下问题必须修复后才能进入执行阶段：

- 事实强度高于甲方原文，或出现本屏证据之外的新承诺。
- 标题只报品名、材质、结构或参数，没有用户结论。
- 广告腔、说明书腔、内部术语或人群刻板标签。
- 三层文案重复、跨屏任务重复、任一字段为残句。
- 文字超过移动端长度限制或无法让用户一句话复述。

修复时只改被点名字段，保留 `screenId / subjectKey / userQuestion / claimScope / evidenceIds` 与甲方事实原意。
